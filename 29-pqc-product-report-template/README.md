# 29-pqc-product-report-template

## 🧠 Descripción

Plantilla de reporte empresarial para seguridad post-cuántica.

Este proyecto pertenece a la ruta:

```txt
Building Projects
```

y acompaña directamente al proyecto:

```txt
AI Engineer Proyecto 57 — post-quantum-security-product-blueprint
```

Mientras AI Engineer trabaja el blueprint completo de un producto de seguridad post-cuántica, este Building Project crea una plantilla clara, reutilizable y presentable de reporte empresarial.

La idea es mostrar:

```txt
cliente
→ crypto inventory
→ risk scoring
→ executive summary
→ recommendations
→ migration roadmap
→ report template
```

Este proyecto no busca crear un scanner completo.

Busca crear un activo profesional para comunicar riesgo post-cuántico de forma responsable.

---

## 🎯 Objetivo

Crear una plantilla de reporte para un producto empresarial de seguridad post-cuántica.

El objetivo es explicar:

* Qué sistemas o algoritmos se revisaron.
* Qué riesgos existen.
* Qué significa exposición RSA/ECC.
* Qué prioridad tiene cada área.
* Qué recomendaciones PQC se proponen.
* Qué fases de migración podrían seguirse.
* Qué límites tiene el análisis.
* Cómo comunicar riesgo sin alarmismo.

## 🧩 Módulos

### Módulo 1 — Customer Context

Definir contexto del cliente.

Incluye:

* Industria.
* Sistemas críticos.
* Datos sensibles.
* Nivel de madurez.
* Preocupación principal.
* Alcance del reporte.
* Nivel de exposición conceptual.

Pregunta central:

```txt
¿Qué tipo de empresa necesita este reporte?
```

---

### Módulo 2 — Crypto Inventory Section

Diseñar sección de inventario criptográfico.

Incluye:

* Algoritmo.
* Protocolo.
* Sistema.
* Tipo de dato protegido.
* Criticidad.
* Ubicación conceptual.
* Observaciones.

Pregunta central:

```txt
¿Qué necesito inventariar antes de hablar de migración PQC?
```

---

### Módulo 3 — RSA / ECC Exposure Notes

Crear notas de exposición RSA/ECC.

Incluye:

* Dónde aparece RSA.
* Dónde aparece ECC.
* Qué sistemas dependen de ellos.
* Qué datos podrían estar protegidos.
* Qué riesgo conceptual existe.
* Qué no se puede afirmar sin auditoría real.

Pregunta central:

```txt
¿Cómo explico exposición criptográfica sin exagerar?
```

---

### Módulo 4 — Risk Scoring Section

Crear sección de puntuación de riesgo.

Incluye:

* Riesgo bajo.
* Riesgo medio.
* Riesgo alto.
* Criticidad.
* Exposición.
* Vida útil del dato.
* Prioridad de revisión.

Pregunta central:

```txt
¿Cómo comunico riesgo sin alarmismo?
```

---

### Módulo 5 — Executive Summary

Crear resumen ejecutivo.

Incluye:

* Hallazgo principal.
* Nivel de exposición.
* Prioridad.
* Impacto potencial.
* Recomendación corta.
* Lenguaje no técnico.
* Advertencias responsables.

Pregunta central:

```txt
¿Cómo entiende esto una persona ejecutiva?
```

---

### Módulo 6 — PQC Recommendation Cards

Crear tarjetas de recomendación.

Incluye:

* Sistema afectado.
* Riesgo.
* Acción sugerida.
* Prioridad.
* Dependencia.
* Limitación.

Pregunta central:

```txt
¿Qué recomendación puede ser útil sin prometer certeza falsa?
```

---

### Módulo 7 — Migration Roadmap Section

Crear sección de roadmap.

Incluye:

* Fase de inventario.
* Fase piloto.
* Fase de migración.
* Fase de validación.
* Fase de monitoreo.
* Riesgos operativos.
* Siguiente paso recomendado.

Pregunta central:

```txt
¿Cómo convierto el diagnóstico en plan de acción?
```
